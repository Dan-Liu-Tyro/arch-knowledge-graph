# Getting the foundation right outranks starting the visible work

Time spent on structure, instrumentation, and working practice before producing the
project's actual content is an investment, not a delay — and pressure to start
delivering is not on its own a reason to stop.

**Evidence.** I argued twice that the schema should be pressure-tested against real
entities before more scaffolding was added, citing cost already spent on structure
around an untested schema. The response was explicit: "It's ok to get foundation
right before rushing into working on the project itself."

**Implication.** Do not treat unbuilt features as an argument against foundational
work, and do not re-raise it once answered. The useful challenge is whether a given
piece of foundation is *the right one* — not whether foundation should come first.
That reframes my objection rather than dismissing it: the schema-versus-scaffolding
question is still live, but as "is this the foundation that matters most next," not
"should we be building foundation at all."
